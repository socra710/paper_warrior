# 종이전사 초기 프로젝트 기반 설계

## 목표

기획서 v2.0과 포함된 콘셉트 시트를 읽기 쉬운 Markdown 개발 문서로 정리하고, Godot 4 웹 우선 프로젝트의 초기 구조를 준비한다. 이번 단계는 엔진 기반 및 화면 흐름 확인에 한정하며 전투, 성장, 저장, 콘텐츠 등 실제 게임 기능은 구현하지 않는다.

## 근거가 된 기획 원칙

- 귀여운 종이 접기 전사 한 명을 중심으로 하는 2D 픽셀 방치형 RPG이며 웹 우선이다.
- 캐릭터는 큰 정사각형 머리/몸통, 작은 얼굴, 짧은 각진 팔다리와 민트·하늘색·크림색 계열 팔레트를 사용한다.
- 종이 접힌 면과 그림자를 픽셀 가독성을 해치지 않게 표현한다. 삽입된 콘셉트 시트는 방향 참고용이며 실제 게임 에셋으로 바로 쓰지 않는다.
- 추후 전투 계산은 화면 표현과 분리하고, 스테이지·보상 등 조정 가능한 콘텐츠는 데이터로 관리한다.
- 에이전트는 먼저 관련 문서를 확인하고 변경 파일과 검증 방법을 제시하며, 실행하지 않은 검사를 성공했다고 보고하지 않는다.

## 구조 결정

### 씬 흐름

각 화면을 독립 씬으로 유지한다. 프로젝트 시작 씬은 Splash이며, 짧은 표시 후 Loading으로 자동 이동하고 Loading은 준비 단계용 짧은 대기 후 Title로 이동한다. Title의 시작 입력은 비어 있는 Main Game 씬을 연다. Splash/Loading은 화면 흐름의 뼈대일 뿐 실제 초기화·로딩 시스템을 구현하지 않는다.

Main Game 씬에는 플레이어, 적, HUD 또는 전투 기능을 넣지 않는다. 네 화면을 분리하면 이후 각 화면을 독립적으로 대체·검증할 수 있다. 단일 씬 내 화면 상태 전환도 가능하지만, 이번 단계에서는 네 개의 명시적 목적지를 더 쉽게 읽고 점검할 수 있으므로 선택하지 않는다.

### 프로젝트 레이아웃

- `scenes/main/`: Splash, Loading, Title, Main Game 씬
- `scripts/main/`: 각 화면의 최소 이동/진입 스크립트
- `assets/`: 캐릭터, 몬스터, 장비, 꾸미기, 배경, 이펙트, 아이콘, 오디오
- `assets/fonts/`: 브라우저에서도 한글 UI가 표시되도록 OFL 글꼴과 라이선스
- `data/`: 아이템, 몬스터, 스테이지, 성장 데이터의 향후 위치
- `docs/`: 기획서, 아트 기준, 기술 구조, 작업 단계
- `.github/copilot-instructions.md`: 작고 검증 가능한 변경을 위한 작업 규칙

아직 콘텐츠 에셋이나 게임 밸런스 데이터를 만들지 않는다. 빈 폴더는 `.gitkeep`으로 추적한다. 한국어 화면에는 라이선스를 함께 보존하는 Noto Sans KR을 사용한다. Web Export는 Godot 4 Web preset으로 설정하고 렌더링은 웹 호환성이 높은 Compatibility 경로를 기준으로 한다.

### 문서

- `docs/GAME_DESIGN.md`: 원문의 13개 항목, 표, MVP 및 미확정 사항을 보존한 정본
- `docs/ART_GUIDE.md`: 캐릭터 규칙, 애니메이션, 규격, 레이어, 명명 및 메타데이터
- `docs/TECHNICAL_DESIGN.md`: 초기 구조, 화면 흐름, 웹 Export 및 검증
- `docs/TASKS.md`: 기획서의 단계별 로드맵과 현재 기반 단계의 완료 상태
- `README.md`: 빠른 실행·Export 안내 및 프로젝트 링크

표는 Markdown 표로 변환하고, 기획서의 미확정 값을 임의로 결정하지 않는다. 삽입 이미지는 원문 참고 자료이며 실제 스프라이트로 사용 전 프레임 분리, 투명 배경, 크기·팔레트·기준점 검수가 필요하다고 명시한다.

## 대안과 선택

1. **단일 씬 + 화면 상태 스크립트**: 파일 수는 줄지만 화면 경계와 독립 검증이 흐려진다.
2. **Splash/Loading/Title/Main Game 독립 씬**: 파일은 조금 늘지만 요청된 흐름이 구조에 그대로 드러나고 향후 교체가 단순하다. 이 방식을 선택한다.
3. **기획서 한 파일만 변환**: 원문을 한곳에서 찾기는 쉽지만 구현자가 찾을 아트·기술 기준이 혼재한다. 전체 정본을 유지하면서 실무 가이드를 별도 문서로 나눈다.

## 범위 제외

전투·성장·인벤토리·저장·오프라인 보상·로그인·결제·캐릭터 에셋·사운드·배포 자동화는 이번 단계에서 구현하지 않는다. Web Export preset과 로컬 검증만 준비한다.

## 검증 기준

1. Godot 4 headless 에디터 검사에서 프로젝트와 네 씬/스크립트가 오류 없이 로드된다.
2. Web Export preset으로 HTML 빌드가 생성된다.
3. 로컬 웹 서버를 통해 빌드를 열고 Splash → Loading → Title 흐름 및 시작 입력 후 빈 Main Game 화면을 확인한다.
4. 문서에 원문 게임 방향, 아트 규칙, 기술 구조, 데이터 초안, MVP 경계, 미확정 사항이 보존되고 사용법 및 에이전트 규칙이 명시된다.
