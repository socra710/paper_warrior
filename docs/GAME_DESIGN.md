## 1. 게임 비전 및 핵심 차별점

종이전사는 종이로 접어 만든 작은 전사 한 명을 플레이어가 오랫동안 성장시키는 게임이다. 여러 캐릭터를 수집하는 구조가 아니라 하나의 전사에게 장비를 입히고, 종이 공작으로 능력을 강화하고, 꾸미기 파츠로 외형을 바꾸는 데 집중한다.

### 핵심 가치

- **단일 캐릭터에 대한 애착:** 처음 만난 전사가 장비와 외형, 성장 기록을 쌓으며 플레이어의 전사가 된다.
- **종이 소재를 게임 규칙으로 활용:** 접기·겹치기·문양이 각각 다른 성장 방향을 제공한다.
- **가볍고 귀여운 픽셀 표현:** 종이의 접힌 면과 그림자를 제한된 픽셀 팔레트로 표현한다.
- **짧게 접속해도 성장하는 방치형 구조:** 자동 전투와 오프라인 보상으로 반복 플레이 부담을 줄인다.
- **웹 우선, 모바일 확장:** 브라우저에서 먼저 검증하고 Android 빌드로 확장한다.

> “종이 한 장에서 태어난 작은 전사를 접고, 겹치고, 꾸미며 나만의 전사로 성장시키는 방치형 RPG.”

## 2. 캐릭터 디자인 및 표현 규칙

### 2.1 기본 캐릭터 콘셉트

기준 캐릭터는 정사각형에 가까운 종이 머리/몸통, 작은 점 형태의 눈과 단순한 미소, 접힌 종이처럼 각진 팔·다리, 민트·하늘색·크림색 계열의 부드러운 색상을 사용한다. 3D 페이퍼크래프트 느낌을 유지하되 게임 내 표현은 읽기 쉬운 2D 픽셀 아트로 단순화한다.

| 요소 | 디자인 규칙 |
|---|---|
| 머리/몸통 | 큰 정사각형 종이 형태. 얼굴이 캐릭터 인지의 중심이 되도록 단순화 |
| 얼굴 | 작은 세로 눈 2개와 짧은 미소. 감정은 눈·입·기호로만 최소 변경 |
| 팔·다리 | 접힌 종이 조각처럼 각진 실루엣. 애니메이션 시 관절을 과도하게 세분화하지 않음 |
| 색상 | 민트, 청록, 하늘색, 크림색을 기본 팔레트로 사용. 강한 형광색 지양 |
| 외곽선 | 짙은 남청색 계열. 캐릭터가 배경에서 명확히 분리되도록 유지 |
| 종이 질감 | 픽셀 수를 해치지 않는 범위에서 접힌 면, 종이 그림자, 하이라이트로 표현 |
| 비율 | 큰 머리/몸통과 짧은 팔다리의 치비 비율. 작은 화면에서도 표정이 보이도록 설계 |

### 2.2 캐릭터 애니메이션

방치형 전투에서는 이동 애니메이션보다 대기·공격·피격의 품질이 중요하다. MVP는 3개 애니메이션을 먼저 완성하고 나머지는 콘텐츠 확장 단계에서 추가한다.

| 분류 | MVP 동작 | 후속 동작 |
|---|---|---|
| 기본 | 대기, 걷기 또는 제자리 이동 | 달리기, 점프, 승리 |
| 전투 | 공격 1종, 피격 | 연속 공격, 스킬, 회피, 사망/부활 |
| 표정 | 기본, 기쁨 | 놀람, 슬픔, 화남, 당황 |
| 상태 | 레벨업, 버프 표시 | 디버프, 회복, 희귀 드롭 연출 |

## 3. 핵심 플레이 루프와 전투

**자동 전투 → 골드/재료 획득 → 레벨·장비·종이 공작 강화 → 더 높은 스테이지 도전 → 반복**

### 전투 기본 규칙

- 전투는 기본적으로 자동 진행한다. 플레이어는 성장과 장비 선택으로 전투 결과에 영향을 준다.
- 전투 계산은 렌더링/애니메이션과 분리된 순수 로직으로 구현한다.
- 공격 속도, 공격력, 치명타, 방어력, 피해 감소 등은 독립된 능력치로 관리한다.
- 전투 화면은 캐릭터와 몬스터의 위치, 체력 표시, 공격 이펙트, 획득 보상에 집중한다.
- MVP에서는 복잡한 실시간 조작이나 PvP를 제외한다.

### 전투 화면 구성

| 영역 | 표시 내용 |
|---|---|
| 상단 | 현재 지역/스테이지, 전투력 또는 진행 정보 |
| 중앙 | 종이전사와 몬스터, 공격·피격 애니메이션 |
| 캐릭터 정보 | HP 및 필요 시 버프/상태 아이콘 |
| 하단 | 골드·재료 획득량, 성장/장비/공작 메뉴 진입 |
| 보상 연출 | 골드, 장비, 재료 획득 시 간단한 픽셀 이펙트 |

## 4. 성장 시스템

### 4.1 기본 레벨

기본 레벨은 초반 성장과 기능 해금의 기준이다. 최대 레벨은 50 또는 100을 후보로 두며 아직 확정하지 않는다. 레벨업 시 기본 능력치가 증가하고 일부 콘텐츠가 해금된다.

| 항목 | 초기 설계 |
|---|---|
| 경험치 | 전투 처치 및 스테이지 보상으로 획득 |
| 레벨업 | 필요 경험치 충족 시 자동 또는 확인형 레벨업 |
| 기본 능력치 | 공격력, 체력, 방어력 중심 |
| 상한 | 50 또는 100 검토 후 밸런스 테스트로 결정 |

### 4.2 종이 공작 성장

기본 레벨 이후에도 장기 성장 동기를 제공하는 종이전사의 핵심 시스템이다.

| 갈래 | 테마 | 대표 능력치/효과 | 역할 |
|---|---|---|---|
| 접기 | 공격 특화 | 공격력, 치명타 피해, 스킬 피해 | 빠른 처치와 공격 중심 빌드 |
| 겹치기 | 생존 특화 | 최대 체력, 방어력, 피해 감소 | 안정적인 전투와 상위 스테이지 버티기 |
| 문양 | 특수 능력 | 공격 속도, 보상 효율, 발동형 효과 | 전투 스타일과 파밍 효율 변화 |

각 갈래는 재료와 골드 등을 소비해 단계적으로 강화한다. 초기에는 선택을 되돌리는 복잡한 재설정 기능을 넣지 않는다. 재접기/환생 시스템은 MVP에서 제외하고 장기 성장 소진 시점에 별도 검토한다.

### 4.3 능력치 원칙

- 기본 능력치와 장비 추가 능력치, 종이 공작 추가 능력치를 구분해 계산한다.
- 최종 전투 능력치는 하나의 계산 모듈에서 산출한다.
- UI는 최종 수치와 각 성장 출처를 구분해 표시할 수 있도록 한다.
- 초기에는 능력치 종류를 제한해 밸런스와 UI 복잡도를 낮춘다.

## 5. 장비 및 꾸미기

### 5.1 장비

| 항목 | MVP 방향 |
|---|---|
| 슬롯 | 무기, 방어구 |
| 획득 | 전투 드롭 또는 스테이지 보상 |
| 강화 | 골드와 재료를 소비하는 단순 강화 |
| 등급 | 일반/희귀/에픽 등 3단계부터 시작 |
| 실패 페널티 | 강화 실패·파괴 시스템은 초기 제외 |
| 확장 | 장신구 슬롯 및 세트 효과는 후속 추가 |

### 5.2 꾸미기

꾸미기는 전투 능력치와 분리된 외형 전용 시스템이다. 단일 기본 캐릭터에 파츠를 레이어로 조합하여 다양한 외형을 제공한다. 유료 BM은 후속 검토하며 MVP에서는 무료 획득형 아이템만 제공한다.

| 슬롯 | 아이템 예시 | 초기 목표 수량 |
|---|---|---:|
| 머리 장식 | 종이 왕관, 리본, 꽃, 작은 모자 | 5종 |
| 스티커 | 별, 하트, 구름, 동물 얼굴 | 5종 |
| 문양/낙서 | 볼 홍조, 손그림 선, 작은 기호 | 5종 |
| 종이 재질 | 색종이, 한지, 크라프트지 | 3종 |
| **합계** | 무료 꾸미기 파츠 목표 | **약 18종** |

- 스티커의 위치 이동, 크기 조절, 회전, 좌우 반전 및 제한된 다중 배치는 후속 기능으로 검토한다.
- 자유 그림 그리기는 저장·검수·악용 방지 부담으로 MVP에서 제외한다.
- 꾸미기 아이템은 도감/업적/스테이지 보상 등 게임 플레이로 획득하도록 한다.
- 캐릭터의 전신 스프라이트를 아이템마다 새로 만들지 않고 파츠 레이어를 재사용한다.

## 6. 스테이지·몬스터·보상

| 콘텐츠 | MVP 목표 | 설계 원칙 |
|---|---|---|
| 지역 | 초기 지역 1개 | 배경 에셋을 재사용하고 색상/소품으로 변주 |
| 일반 몬스터 | 3종 | 실루엣과 색상으로 구분. 기본 전투 패턴은 단순화 |
| 보스 | 1종 또는 MVP 이후 | 일반 몬스터보다 체력·공격 연출을 강화 |
| 보상 | 골드, 경험치, 장비/강화 재료 | 드롭 테이블 데이터화 |
| 스테이지 | 연속 진행 가능한 짧은 구간 | 난이도와 보상 증가 규칙을 데이터로 관리 |

스테이지 난이도와 보상 수치는 코드에 직접 고정하지 않고 데이터 파일로 관리한다. 초기에는 콘텐츠 양보다 성장 루프가 재미있고 이해하기 쉬운지 검증한다.

## 7. 아트 에셋 제작 및 관리

### 7.1 제작 원칙

- AI는 캐릭터 콘셉트, 몬스터, 장비, 배경의 초안 제작에 사용한다.
- AI 생성 이미지를 그대로 게임에 넣기보다 프레임 분리, 투명 배경, 크기 정규화, 팔레트 검수를 수행한다.
- 캐릭터의 기본 실루엣과 얼굴 비율을 기준 이미지로 고정해 생성물의 일관성을 유지한다.
- 스프라이트는 동일한 캔버스 크기와 기준점(anchor)을 사용한다.
- 애니메이션 프레임은 캐릭터 중심점과 발 위치가 흔들리지 않도록 정렬한다.

### 7.2 권장 에셋 규격 초안

| 에셋 | 초기 권장 규격 | 비고 |
|---|---|---|
| 기본 캐릭터 | 64×64 또는 96×96 픽셀 | 실제 화면 크기 테스트 후 확정 |
| 애니메이션 | 동작별 스프라이트 시트 | 프레임 크기 동일, 프레임 순서 명시 |
| 아이콘 | 32×32 또는 48×48 픽셀 | 장비·재료·상태 아이콘 |
| 이펙트 | 32×32~96×96 픽셀 | 효과별 개별 시트 |
| 배경 | 화면 비율에 맞는 타일/레이어 | 반복 가능한 요소 우선 |

위 크기는 시작을 위한 가이드이며, 최종 해상도와 화면 배율을 확정한 뒤 전체 에셋에 일괄 적용한다.

### 7.3 레이어 순서

| 순서 | 레이어 | 예시 |
|---:|---|---|
| 1 | 후면 이펙트 | 오라, 반짝임 |
| 2 | 등/망토 장식 | 망토, 날개, 등 장식 |
| 3 | 기본 캐릭터 | 머리/몸통/팔/다리 |
| 4 | 머리 장식 | 왕관, 리본, 꽃 |
| 5 | 스티커/문양 | 볼 홍조, 별, 낙서 |
| 6 | 전면 이펙트 | 레벨업 빛, 공격 효과 |

### 7.4 에셋 폴더 및 메타데이터

파일명은 용도와 동작을 알아볼 수 있게 통일한다. 예: `warrior_idle_01.png`, `warrior_attack_01.png`, `hat_paper_crown.png`, `effect_levelup_01.png`.

에셋 메타데이터에는 `asset_key`, `category`, `slot`, `frame_size`, `frame_count`, `anchor`, `layer_order`, `rarity`, `unlock_source`를 기록한다.

## 9. 저장·오프라인 보상·플랫폼 확장

### 9.1 저장

- 저장 데이터에 `schema_version`을 포함한다.
- 캐릭터 레벨/경험치, 재화, 장비, 종이 공작 단계, 꾸미기 설정, 스테이지 진행, 마지막 접속 시각을 저장한다.
- 저장 데이터가 없거나 손상된 경우 기본 상태로 복구할 수 있어야 한다.
- 저장 구조가 바뀌면 버전별 마이그레이션 함수를 제공한다.

### 9.2 오프라인 보상

브라우저나 앱이 종료된 동안 실제 전투를 계속 실행하지 않는다. 마지막 저장 시각과 재접속 시각의 차이로 오프라인 시간을 산출하여, 제한된 최대 시간과 보상 계수를 적용해 보상을 지급한다. MVP는 로컬 시간 기반으로 구현하되 시간 조작 방지와 다중 기기 동기화는 서버 도입 시 강화한다.

### 9.3 플랫폼

| 플랫폼 | 배포 방식 | 주의 사항 |
|---|---|---|
| 웹 | Godot Web Export → GitHub Pages 또는 정적 호스팅 | 브라우저 호환성, 로딩 크기, WebGL 2.0, 저장 권한 확인 |
| Android | Godot Android Export → APK/AAB | Android SDK/JDK 설정, 터치 UI, 화면 비율, 저장/일시정지 테스트 |
| 서버 기능(후속) | 별도 백엔드/Firebase 등 검토 | 로그인, 랭킹, 기기 간 저장, 보상 검증이 필요해질 때 도입 |

웹과 Android는 동일한 게임 로직과 에셋을 최대한 공유하되, 입력·화면 배치·저장·일시정지 동작은 플랫폼별로 검증한다.

## 10. MVP 범위와 개발 로드맵

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 0. 기반 | Godot 프로젝트, GitHub, Copilot 규칙, 웹 Export 설정 | 웹에서 빈 게임 화면 실행 |
| 1. 캐릭터 | 기본 전사, 대기/공격/피격 애니메이션 | 캐릭터가 자연스럽게 반복 동작 |
| 2. 전투 | 몬스터 1~3종, 자동 전투, HP/보상 | 전투가 자동으로 진행되고 결과가 계산됨 |
| 3. 성장 | 레벨, 골드, 능력치 강화 | 전투 보상으로 캐릭터 성장 |
| 4. 장비 | 무기/방어구 획득·장착·강화 | 장비가 능력치와 외형에 반영 |
| 5. 종이 공작 | 접기/겹치기/문양 성장 | 세 성장 갈래가 서로 다른 효과 제공 |
| 6. 꾸미기 | 초기 무료 파츠 약 18종 중 일부 적용 | 장착/해제 및 외형 저장 |
| 7. 저장 | 저장/불러오기, 오프라인 보상 | 재접속 후 진행 상태 복구 |
| 8. 배포 | 웹 빌드 자동화 및 모바일 브라우저 검증 | 공개 URL에서 플레이 가능 |

## 12. AI 에이전트 작업 규칙 (GitHub Copilot)

1. 작업 전 관련 씬, 스크립트, 데이터 파일과 문서를 먼저 확인한다.
2. 한 번에 하나의 기능 단위로 구현하고 변경 파일 목록을 먼저 제시한다.
3. 게임 규칙/계산 로직과 화면 표현을 분리한다.
4. 기존 구조를 임의로 전면 변경하거나 새 플러그인을 무단 추가하지 않는다.
5. 주요 함수와 복잡한 로직에는 한국어 주석을 작성한다.
6. 기능 구현 후 Godot 실행, 관련 테스트, 웹 Export를 검증한다.
7. 실행하지 않은 테스트는 성공했다고 보고하지 않는다.
8. 에셋을 추가할 때 규격·프레임 수·기준점·레이어 순서를 메타데이터에 기록한다.
9. 문서와 실제 구현이 달라지면 `docs/TASKS.md` 및 기술 문서를 함께 갱신한다.

### Copilot 첫 작업 지시 예시

> 종이전사 기획서와 아트 가이드를 기준으로 Godot 4 프로젝트 초기 구조를 구성해줘. 이번 단계에서는 실제 게임 기능을 구현하지 말고, 씬/스크립트/데이터/에셋 폴더와 웹 Export 설정, Copilot 작업 규칙, 개발 문서를 준비해. 변경 파일 목록과 실행·검증 방법을 먼저 제시하고, 완료 후 빈 게임 화면이 웹에서 실행되는지 확인해줘.

## 최종 기획 요약

종이전사는 귀여운 종이 접기 전사 한 명을 중심으로 하는 2D 픽셀 방치형 RPG다. 기본 레벨과 장비, 접기·겹치기·문양의 종이 공작 성장, 무료 꾸미기 파츠 조합으로 장기 성장과 애착을 제공한다. Godot 4로 개발하고 GitHub Copilot을 활용해 작은 기능 단위로 구현한다. 웹을 먼저 출시하고 동일 프로젝트를 Android로 확장하되, MVP에서는 자동 전투·핵심 성장·저장 루프의 완성도를 우선한다.
